# Support

Use GitHub issues for project support that benefits from public tracking:

- reproducible front-end bugs
- documentation gaps
- confusing local development or build behavior
- feature requests that fit the IPFS-first architecture

Before opening an issue, check the existing issues, `README.md`, and the docs in
`docs/`.

## Not For Public Issues

Do not open public issues for:

- security vulnerabilities or suspected funds-at-risk scenarios
- private keys, wallet seed phrases, API keys, or other secrets
- personal account recovery or wallet support
- guaranteed response-time requests

For security reports, follow `SECURITY.md`.

## Useful Issue Details

Good support requests include the affected route or package, browser and wallet,
chain, RPC or provider details, commit SHA, steps to reproduce, expected result,
actual result, and screenshots or logs when relevant.
